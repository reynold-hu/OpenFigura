# 上游代码复用与减法守则

用户2026-10-09明确要求：优先拉取成熟源码，迁入后删减，不重新起草已有算法。
这条约定适用于之后的建模、脸部、蒙皮、渲染和动作工作。

1. 新算法前先查`Local/Opensource`和对应官方源码，给出可复用模块。已有合适
   实现时默认迁入；自行实现须先记录具体许可、依赖、质量或接口阻碍，不凭偏好。
2. 先克隆固定commit，研究输入/输出、数值单位、资源加载、设备选择和调用链。
   不把README演示、代码存在或CPU renderer当成端到端推理已通过。
3. 代码、weights、数据、第三方子模块分别核许可。保留LICENSE/NOTICE/署名；
   不把第三方代码改标AGPL，不以开源徽标推断所有资产可商用。
4. 合适源码先完整复制到仓库工作副本，排除.git等管理信息；逐文件hash确认，
   再做减法。例图、摄像头/网页演示、训练入口、平台binary等按需要移走。
   删除文件留主仓库`.local/runs/<batch>/removed/`，原clone保留；可按原相对路径恢复。
5. 优先不改算法。允许薄adapter处理OpenFigura契约、私有输入、hash、失败报告、
   CPU/GPU选择与包路径；源修改逐条列patch理由和前后hash，区分算法/接线变化。
6. 可选重依赖隔离，不能让基础CLI/MCP导入就加载torch/weights；不要为一个
   算法直接套整个上游UI、环境或下载脚本。审查后只安装实际需要的依赖。
7. 保留上游已有测试与结果格式；增加输入、单位、坏值、真实程序与打包检查。
   没有weights只测了几何函数，应直说；正式adapter未接好不能标已集成推理。
8. 每批记录仓库URL、commit、许可证、保留/移走/修改文件、恢复路径、依赖及
   实际验证。发布包也带源记录和许可；模型改进必须附真实同条件前后图。
9. 原资产/golden不覆盖，阈值不放宽，失败不得包装成成功；版本冻结后再运行
   重实验，避免编辑worker与正在执行的worker重叠。
