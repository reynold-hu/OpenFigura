# OpenFigura 产品设计：低门槛端到端 3D 资产工具链

**日期：** 2026-10-08  
**状态：** 设计已确认，等待实现计划  
**目标用户：** 独立游戏开发者为主，同时服务普通创作者和 Agent／自动化开发者

## 1. 产品定位

OpenFigura 是一个本地运行、可检查、可重跑的 3D 资产制作工具链。它把参考图或已有模型处理成可以在 Blender、Godot、Unity 等工具中继续使用的资产，并把生成、材质、拓扑、骨架、动作、碰撞和导出作为一条可追踪的流程连接起来。

它不是一个聊天 Agent，也不是必须依赖云端的图片转模型网站。专用模型和几何算法负责实际计算；用户可以通过向导、CLI 或 MCP 使用同一套能力。Agent 只负责理解用户意图、选择工具和参数、读取检查结果，不负责逐顶点修改模型或逐帧编写动作。

产品的核心承诺是：

- **端到端：** 从参考图开始，最终可以得到可检查、可绑定、可动作、可导出的角色资产。
- **低门槛：** 基础处理不要求高端 GPU；大型生成模型按设备能力启用、排队或转交到另一台计算节点。
- **可控：** 每个阶段都有中间产物和检查报告，用户可以替换失败阶段而不必重新开始。
- **可追溯：** 输入、参数、后端版本、设备、输出哈希和失败原因都写入任务记录。
- **可扩展：** 生成模型、材质模型、自动骨架和动作模型通过后端接口接入，不把某一个商业平台写死在产品里。

OpenFigura 不承诺所有输入都达到商业云服务的相同视觉质量。它承诺的是一套能持续比较、修正和复用的本地流程：看得见中间结果，知道哪里失败，失败结果不会被误导性地导出。

## 2. 用户与使用场景

### 2.1 独立游戏开发者（第一目标）

开发者上传角色设定图，希望得到可进入游戏制作流程的模型。重点不是只有一张漂亮的预览图，而是同时检查脸部和服装还原、网格密度、材质、骨架、动作、穿插和导出格式。

典型结果是：一个原始高模、一个可编辑或可继续处理的网格、游戏用三角网格、贴图与材质、绑定骨架、动作片段、碰撞代理，以及一份能说明每个阶段的任务记录。

### 2.2 普通创作者

创作者只想把一张角色图变成可以旋转查看或放进 Blender 的模型。默认向导隐藏复杂参数，只在输入质量、预计耗时、显存需求或检查失败时给出明确说明。

### 2.3 Agent／自动化开发者

Agent 通过 MCP 或 CLI 提交任务、查询状态、读取检查报告、重跑某一阶段并导出结果。工具返回结构化状态和文件路径，不要求 Agent 解析渲染截图后猜测任务是否成功。

## 3. 交互模型：分层端到端工作流

默认交互是一条完整向导，阶段可以展开查看：

```text
参考图／已有模型
        ↓
输入检查与预处理
        ↓
几何生成或模型导入
        ↓
多视角材质与纹理精修
        ↓
拓扑、UV、高低模与烘焙
        ↓
骨架预测、蒙皮与变形检查
        ↓
动作重定向、IK 与接触检查
        ↓
碰撞代理、游戏导出与证据包
```

默认模式下，用户只需要选择参考图、目标风格、输出目标和设备策略。系统按阶段生成结果卡片，每张卡片显示状态、耗时、使用的后端、设备、预览和可执行动作：继续、查看、替换后端、重跑、接受或拒绝。

高级用户可以展开阶段并修改参数。阶段之间通过带哈希的资产引用连接；只要上游输入没有变化，重跑下游阶段不重新生成上游结果。用户拒绝某个候选后，候选仍保留在任务证据目录，但不能从普通导出路径交付。

三种入口共用同一个核心：

- **本地向导／未来 Web 工作台：** 适合普通创作者和游戏开发者，显示任务卡片、预览和检查结果。
- **CLI：** 适合脚本、批处理和 CI，参数显式，结果可重复读取。
- **MCP：** 适合 Codex、opencode、Claude 等 Agent，提供结构化工具调用、状态查询和结果引用。

任何入口都不能绕过核心校验。前端只负责交互和参数传递，不复制生成、检查或导出逻辑。

## 4. 功能范围

### 4.1 输入与预处理

支持单张正面图、带多视角的输入集合和已有 GLB／OBJ／FBX 资产。预处理负责分辨率、主体抠图、相机方向、透明边缘、重复视角和明显遮挡的检查。错误输入不会静默进入长时间生成任务；系统给出可修复的原因和建议。

### 4.2 几何生成与导入

几何后端可以是 Pixal3D、TRELLIS、Hunyuan 或其他符合接口的本地后端。后端只负责生成候选，OpenFigura 负责保存输入哈希、参数、运行设备、网格报告和渲染证据。已有模型可以跳过生成阶段直接进入材质、拓扑或绑定流程。

### 4.3 材质与细节

材质流程与几何流程分开。它可以使用多视角生成、可见像素投射、法线／粗糙度估计和高低模烘焙来恢复脸部、头发、衣物纹理和图案。参考图中不可见的区域必须标记为推断区域；投射得到的图案与生成得到的背面不能混成一个无法解释的结果。

### 4.4 拓扑、UV 与网格交付

流程保留两类结果：用于继续编辑或变形的可编辑网格，以及用于游戏运行的三角化网格。四边形重拓扑不是无条件优先；系统报告四边形占比、三角化后的面数、形状误差、薄片和手指是否被融合。GLB 游戏交付可以是三角面，Blender 编辑源保留实际的拓扑来源。

### 4.5 骨架、蒙皮与动作

自动骨架后端负责预测关节和权重，OpenFigura 负责连续性检查、权重归一化、骨架命名映射和变形渲染。动作后端负责导入公开动作、视频或文本动作结果，并通过目标骨架重定向和 Blender／Godot 原生 IK 生成可复查的动作片段。

动作导出前至少检查手与身体、前臂与身体的区域接触。检测到穿插、缺少可播放动作、额外未检查片段或骨架不匹配时，任务失败；失败候选进入隔离目录而不是普通导出目录。布料动力学、全身碰撞和所有风格角色的手指精确绑定属于后续能力，不在第一版中伪装成已解决问题。

### 4.6 碰撞与游戏导出

系统同时提供渲染网格、简化碰撞代理和动作接触报告。碰撞代理用于游戏物理，不能替代动画过程中的手、衣服和身体穿插检查。导出模板至少包括 GLB、Blender 场景、贴图文件夹、动作文件、碰撞代理和 provenance 记录；目标引擎的轴向、单位和骨架约定写入导出报告。

## 5. 硬件与任务调度

产品采用两档设备基线：

### 基础档

16GB 内存的 Apple Silicon 或普通 CPU 电脑可以完成输入检查、模型导入、网格检查、部分拓扑与烘焙、材质投射、已有骨架的动作处理和导出。大型生成与神经自动骨架可以显示为排队、不可用或远程节点任务，而不是让程序崩溃。

### 加速档

8GB 以上 NVIDIA 显存用于本地几何生成、材质模型、自动骨架和动作模型。任务提交时声明预计显存、设备和是否允许并行。默认一张 GPU 只运行一个重模型任务；CPU 预处理、检查和导出可以使用独立 worker。并行数量由资源闸门控制，不把同时提交多个请求误认为显存足够并发推理。

每个任务记录实际设备、峰值内存、后端版本和耗时。设备不满足要求时，系统给出三种明确结果：切换低资源后端、排队等待本机资源、提交到用户配置的计算节点。不会用未验证的降级路径伪装成成功。

## 6. 产出物与质量门

一次完整任务至少产出：

- 可检查的 GLB 游戏资产；
- 可选的 Blender 场景和可编辑网格；
- Albedo、Normal、Roughness 等实际生成或烘焙的纹理文件；
- 骨架、蒙皮权重和经过检查的动作片段；
- 简化碰撞代理或碰撞生成报告；
- 多视角与固定动作帧渲染；
- `provenance.json`、阶段报告、输入和输出哈希、后端许可证信息。

质量门按阶段执行：

1. 输入门：输入主体、分辨率、透明边缘和视角满足后端要求。
2. 几何门：GLB 可解析，网格没有结构性错误，尺寸和方向符合任务约定。
3. 材质门：UV、贴图、材质引用和可见区域通过渲染检查。
4. 变形门：骨架、权重和固定姿态渲染通过；明显的肩、脸、手部异常需要人工拒绝或重跑。
5. 动作门：动作可播放、片段数量明确、关键区域接触检查通过。
6. 导出门：只导出通过相应检查且哈希与成功记录一致的候选。

视觉审美是否满意仍由用户确认，系统不会自动把“技术检查通过”写成“美术认可”。

## 7. Agent 的职责边界

Agent 可以把“把这张图做成一个能在 Godot 中跑的角色”拆成任务参数，提交工作流，等待阶段状态，阅读结构化报告，并在失败时选择重跑或切换后端。Agent 不需要知道每个模型的私有实现，也不应直接修改任务目录中的中间文件。

OpenFigura 工具必须能够在没有 Agent 的情况下运行：用户可以通过向导或 CLI 完成同一条流程。这样可以把稳定性、隐私和可复现性建立在外部算法和工具契约上，而不是建立在某个大语言模型当前的判断能力上。

## 8. 产品阶段

第一阶段交付端到端的可验证主链：输入检查、几何后端适配、材质投射、基础拓扑与烘焙、骨架／蒙皮检查、动作重定向、区域接触、碰撞代理和 GLB／Blender 导出。每个阶段都能从 CLI 和 MCP 调用，向导只展示同一套结果。

第二阶段补齐持久任务状态、GPU 资源闸门、ComfyUI 版本化工作流、可编辑四边形源、高低模烘焙和蒙皮转移。第三阶段再加入 SkinTokens、MoCapAnything、多视角 PBR 精修和资产版本工作台，并以真实硬件实测作为是否启用的依据。

每个阶段以真实角色案例和固定渲染证据验收，不以“能启动”“能生成一个文件”作为完成标准。

## 9. 明确不做的事情

- 不复制 3DGenStudio 的受限项目代码或把其 Community License 当作宽松开源许可。
- 不把 OpenFigura 做成必须依赖聊天模型的 Agent 框架。
- 不要求所有用户购买高端显卡或安装完整的大模型集合。
- 不把未经检查的失败候选放进普通导出路径。
- 不宣称一次生成就天然适合游戏、动作和商业生产。
- 不把不可见区域的推断纹理、自动生成的手指或碰撞代理描述成真实扫描结果。
